# @edgewarn/web-utils

One ESM package for EdgeWARN geometry, time, HTTP clients, alert evaluation, sounding science and weather byte
decoding. Version `2026.11.12-alpha.1` requires Node 22.18+ for development;
portable modules also support browsers and workers with the native APIs described
in the API manuals. `@types/geojson` is included for public GeoJSON declarations.
There are no runtime code dependencies.

```sh
npm install @edgewarn/web-utils@alpha
```

Use the entry point for the functionality you need:

| Import | API |
| --- | --- |
| `@edgewarn/web-utils` | `EdgeWARNDecoder`, `DecodeBudgetExceededError` and decoding types |
| `@edgewarn/web-utils/geo` | Geometry, containment, polygon and solar-position helpers |
| `@edgewarn/web-utils/time` | UTC timestamp parsing, formatting and timeline frame selection |
| `@edgewarn/web-utils/net` | Per-instance EdgeWARN, NWS, WWA, SPC, WPC, reports, Open-Meteo and NHC clients; METAR normalization, S3 listing and `SharedTask` |
| `@edgewarn/web-utils/colormap` | Colormap types, value-to-RGBA lookup, textures, payload parsing and legend stops/ticks |
| `@edgewarn/web-utils/alerts` | Alert priority, classification, geometry, location matching and discussion expiry |
| `@edgewarn/web-utils/alerts/nws` | NWS EAS verification and multi-source point/region alert loading |
| `@edgewarn/web-utils/grib2` | MRMS/model decoding, inventories, GRIB2 packing helpers and optional codecs |
| `@edgewarn/web-utils/nexrad` | NEXRAD Level II/III, cuts, VCP and TVS; station table, elevation assembly, beam geometry and sweep sampling |
| `@edgewarn/web-utils/nexrad/feed` | NEXRAD bucket listings, volume timelines, live polling, Level III reads and the prefix store |
| `@edgewarn/web-utils/met` | Sounding thermodynamics, parcels, indices, kinematics and composites; column building, plate panels, CSV export, observed radiosondes; wind-speed units and apparent temperature |
| `@edgewarn/web-utils/met/plot` | Skew-T, hodograph, wind-barb and time-height geometry as plain numbers |
| `@edgewarn/web-utils/goes` | GOES ABI/HDF5 byte-source readers, band/sector/composite tables and geostationary projection |
| `@edgewarn/web-utils/goes/feed` | GOES bucket listings, range-read sources, band cache and tile pyramid planning |
| `@edgewarn/web-utils/mrms` | MRMS bucket listing, product catalog, lightning, volume geometry and cached downloads |
| `@edgewarn/web-utils/models` | Model engine: grid projections, field math, GRIB2/NetCDF sources, dataset registry and configs, comparison math, HAFS tracks |

```ts
import { distanceMiles } from '@edgewarn/web-utils/geo';
import { EdgeWARNDecoder } from '@edgewarn/web-utils';

const decoder = new EdgeWARNDecoder({ memoryLimitBytes: 64 * 1024 * 1024 });
const field = await decoder.decode(messageBytes, {
  format: 'grib2', mode: 'model', output: 'half',
});
```

The [geometry, time and clients manual](packages/core/README.md) and
[decoder manual](packages/decoders/README.md) and
[alerts manual](packages/alerts/README.md) and
[sounding science manual](packages/met/README.md) and
[models manual](packages/models/README.md) describe the contracts, supported
subsets, explicit codec registration, memory accounting and cancellation.
The `packages/core`, `packages/alerts` , `packages/decoders`, `packages/met`, `packages/sources` and `packages/models` directories are internal source/build
boundaries. They are shipped together and cannot be published independently.
Format entry points remain isolated; the root decoder loads formats on demand.
Private implementation paths are not exported.

This is one published package. Source files in `alerts` import `core` through the
package's own `/net` and `/geo` exports (self-reference); `tsc -b` builds `core`
first through project references. The root `.` export is the decoder entry and
will stay that way; other modules use subpaths. Declaration maps are not shipped
because `src/` is not in the tarball.

Existing imports from `@edgewarn/core` or `@edgewarn/decoders` should switch to
`@edgewarn/web-utils` with the same subpath. The former decoder root import maps
to the new package root. The legacy `@edgewarn/core` and `@edgewarn/decoders` packages are unchanged on npm; deprecate them with `npm deprecate` once consumers have moved.

```sh
npm ci --ignore-scripts
npm test
npm run test:time
npm run lint:pack
npm run check:package
```

The package check builds, packs and installs the single artifact outside the
repository, decodes fixtures, checks every public entry point and verifies strict
TypeScript consumption. Export linting and artifact installation are separate
checks. CI covers Node 22.18 and 24. The original plans record the earlier
separate-package design.

Build output is generated by `prepack`, so both packing and publishing compile
the package.

Releasing uses hand-bumped CalVer prereleases (`YYYY.MM.DD-alpha.N`); there is
no changeset step. To cut a release:

```sh
npm run bump        # increments the -alpha.N counter in package.json,
                    # package-lock.json and README.md
# add a CHANGELOG.md entry for the new version
npm test && npm run check:package
git add -A && git commit -m "chore: bump version to <new version>"
git tag -a v<new version> -m "Release <new version>"
git push origin main --follow-tags
```

Pushing the `v*` git tag triggers `.github/workflows/publish.yml`, which runs
the checks and publishes to the `alpha` dist-tag (or `latest` once the version
is no longer a prerelease) with provenance. The README install hint
(`npm install @edgewarn/web-utils@alpha`) matches that tag.

Supported CI can keep the configured provenance enabled. Publishing is a
separate action; this repository change does not publish or alter npm account
permissions.
